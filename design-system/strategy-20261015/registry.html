治理规则

同一修改同时更新源码、契约与 Figma 映射。新增可兼容形态用 minor；破坏属性或语义用 major；修正文档用 patch。上线前由实际验收结果推进状态。

大公司怎么做，我们借鉴什么

以下描述公开能力，不推断公司内部团队都已使用同一套流程。右列为针对 Nova Island 的建议。

来源已核实的公开实践社区的落地选择
Atlassian · With AI ↗公开 CLI 与 MCP 提供可检索的结构化设计系统内容；页面明确标注所列 skills 目前属于内部资源。为现有 catalog 增加按 id 查询入口；先做本地 registry，之后再包装 MCP。
IBM · Carbon MCP ↗向 AI client 提供组件、token、图标、规范和代码。页面列出的部分迁移能力仍是未来计划。Agent 检索应返回来源和当前版本，避免只凭模型记忆生成组件。
Adobe · Spectrum Design Data ↗公开组件 API schema、tokens、命名 registry，以及 AI 相关资源入口。把属性、类型、默认值、状态和术语放入机器可读契约。
Microsoft · Fluent 2 ↗区分原始值 Global tokens 与具有语义的 Alias tokens，以支持一致的样式和主题。保留原始蓝色阶，将 action、text、surface 等语义绑定到 Figma Variables。
Figma · Code Connect ↗连接设计组件与实际代码，为 MCP 补充实现信息；官方标注 Organization/Enterprise 的 Dev 或 Full 席位可用。当前账号先采用本地映射表。套餐满足后再接 Code Connect；Pro 不作为已具备资格。

推荐组合：B 为主，A 做入口，C 做底座。

  1. 先冻结事实来源。现有产品 tokens.css 为当前基线；保留上下文覆盖；旧主题、官网和 Unico 独立维护。
  2. 先完成 8 个高频组件。Button、Input、Badge、ContentCard、FilterCapsule、Sidebar、Outline、Progress。每项都绑定变量、记录真实来源、列出已实现与缺失状态。
  3. 用 3 条任务验证。发现内容 → 筛选；打开文章 → 返回来源；继续课程 → 更新进度。人工观察视觉与键盘，业务断言检查状态和持久化。
  4. 打通映射后扩大覆盖。当前用本地 fileKey/nodeId/source 对照表；账号满足条件后接官方 Code Connect。共享 Figma Library 的发布权限也需以团队实际能力核实。
  5. 有真实跨项目需求再做 MCP。先用 JSON 按 id 查询即可服务本仓库 Agent；远程工具不是第一阶段前提。
完成标准

核心组件的设计属性、代码契约与状态一一对应；引用 token 可追溯；焦点与错误恢复经过验证；页面在 390px 和桌面可用；每个“已验收”都有证据。当前 50 / 199 是目录条目数，不是生产就绪数量。

当前已知缺口

深色主题未全量验收；搜索焦点反馈、触控命中范围、错误状态覆盖尚有待办；收藏色存在最终 CSS 覆盖。旧 Figma 同步记录为部分完成或配额受限，不能据此宣称当前映射有效。

视觉探索的边界

领域：频道、岛民、阅读、学习路径、实战贡献、知识归档。颜色来自白纸、石墨文字、雾灰工作台、蓝色文件夹、浅色分类签。标志性组合是文件夹 + 双层筛选 + 阅读目录。保持阅读节奏，不加入通用仪表盘大数字、任意霓虹渐变或整齐但失去内容层级的等高卡片。
