页面模式：内容流

一组同类内容按推荐或时间排列。用户在这里筛选、浏览、进入详情，然后返回。文章、论坛、课程、频道、搜索结果、收藏和草稿都属于这个模式。

待确认草案。结构和状态来自原型 articles.js、forum.js、home.js、page-loading.js、catalog.js。数值以原型最终级联为准。

页面骨架

从上到下五个区域。辅助栏可选，其余四个都必须有。

① 页面标题区标题 + 一句说明 + 可选的主要行动
② 筛选条筛选胶囊，滚动时吸顶
④ 辅助栏（可选）活跃成员、说明
③ 内容列表瀑布流卡片或单列行
⑤ 列表终点加载更多 / 已经看完全部内容
区域规则组件 / 来源
① 页面标题区H1 加一句说明当前板块的用途。主要行动（如“＋ 发布帖子”）放右侧，整页只放一个，没有权限时整个隐藏，不显示禁用按钮。滚动后标题淡出。页面标题与分区标题；.forum-heading
② 筛选条放在列表顶部。选项来自内容本身的分类。已选项完整显示，超出的折叠成 +N；“只看精华”“我的帖子”这类开关放在同一条里。筛选胶囊；feedFilterToolbar()
③ 内容列表形态按下一节选择。列表容器设为可聚焦区域：tabindex="0" role="region" aria-label="…列表"。.forum-feed-scroll
④ 辅助栏只放和当前内容相关的信息，比如论坛的活跃讨论者。不放广告式入口。窄屏下不再和列表并排。活跃讨论者
⑤ 列表终点还有更多时显示“加载更多”次按钮；全部加载完后显示“已经看完全部内容”，两侧各一条短横线。底部留白 24px。列表终点；channelFeedFooter()

页面状态

每个内容流页面都要处理下面六种状态（R14）。“空”需要区分两种原因，文案不同。

状态呈现原型中的例子
加载中保留标题区；列表位置显示与内容结构对应的骨架（图文卡、帖子或榜单行）；用 role="status" 播报“正在加载…”；容器设 aria-busy="true"。page-loading.js
正常列表 + 终点。—
筛选后无结果在列表位置原地说明：因为筛选条件导致没有结果，并建议放宽条件。筛选条保留，方便直接修改。“暂无符合条件的精选文章 / 试试其他标签，或取消精选筛选”
板块还没有内容说明原因，并给出第一步行动；没有发布权限时只说明原因。“这个分类还没有讨论” + “写第一篇帖子”
加载失败在主内容区原位显示错误占位和“重新加载”按钮；主导航保持选中；点击后重新显示骨架。见下方差异说明
到底“已经看完全部内容”。catalog.js
已发现的差异：已确认的错误文案是“加载失败，请重试”加“重新加载”，但原型 home.js 目前显示的是“暂时无法加载 / 请稍后再试”加“重新加载”。以已确认的规则为准，原型待修正。

行为规则

规则做法依据
筛选可以分享、可以恢复筛选条件写进 hash 参数，例如 #articles?tag=…&featured=1、#community?topic=…&mine=1。R15
返回原处从详情返回时，恢复原来的筛选条件和滚动位置。R15
筛选始终可用滚动后标题区淡出，筛选条吸顶，用玻璃材质。R12
导航立即响应点击主导航后立即切换选中状态，内容区显示骨架。已确认规则
数字稳定阅读数、赞藏数用等宽数字，变化时不抖动。Foundations
减少动效瀑布流重排、标题淡出都遵循 prefers-reduced-motion。R14

新建一个内容流页

例如给活动、专栏或收藏做列表页时，依次回答下面的问题，就能得到完整的页面规格。

  1. 内容是什么？

    有没有封面，以浏览为主还是以讨论为主？据此选列表形态，以及复用哪个卡片组件（必要时按扩展协议加形态）。

  2. 标题区写什么？

    H1 和一句用途说明；是否需要主要行动，谁有权限。

  3. 按什么筛选？

    列出筛选维度和 hash 参数名；有没有“只看我的”“只看精华”这类开关。

  4. 两种空状态怎么写？

    “筛选后无结果”和“板块还没有内容”各写一句原因和下一步。

  5. 骨架用哪种？

    图文卡、帖子还是榜单行，和最终内容的结构保持一致。

  6. 需要辅助栏吗？

    只有当它能帮助用户决定读什么时才加。

验收清单

  • 标题区最多一个主要行动
  • 筛选写进 hash，刷新后能恢复
  • 从详情返回后，筛选和滚动位置都在
  • 六种页面状态都已实现
  • 两种空状态的文案不同
  • 错误文案和已确认规则一致
  • 长标题完整换行，不截断
  • 1000px / 760px / 390px 下没有横向溢出
  • 列表区域可以用键盘聚焦和滚动
  • 减少动效时没有重排动画
