扩展协议

组件库里没有现成答案时，按这一页做。做完必须通过 check-design.py，新的设计决定必须登记。

步骤

  1. 找现成的

    在 library/catalog.json 里按 summary、usage、avoid 搜索意图，不只搜名称。

  2. 选复用级别

    从上往下，第一条成立的就是答案。

  3. 按角色取 Token

    查下方决策表；先确定元素是什么角色，再取值。

  4. 补齐状态

    默认、悬停、焦点、选中、禁用；加载、两种空状态、原位错误、到底；长文本、390px、键盘。

  5. 检查

    运行 python3 design-system/scripts/check-design.py，新增违规必须为 0；再打开 library-audit.html 看 1000px 和 390px。

  6. 登记

    新组件或新形态写进 scripts/build-library.py，状态标“建议”；新的设计决定写进 DISCUSSION.md 的“待确认”。

复用级别

情况做法例子
现有组件完全满足直接复用，只换内容新频道列表用图文内容卡
结构相同，只差一个属性或状态给现有组件加一个形态内容卡加“活动日期”和“已报名”标签
用几个现有组件能拼出来组合使用，不新建类名，登记为“组合示例”作者卡加关注按钮
以上都不满足新建组件，写进组件库并标为“建议”全新的交互形态

决策表：按角色取 Token

先确定元素的角色，再查表取 Token。组件里只写语义变量，不写原始色值。

颜色角色

想表达使用不要
区域里的主要行动--action-primary 背景，配 --text-on-action（ds-button primary）蓝色按钮；同一区域放多个黑色按钮
次要行动ds-button secondary / ghost在列表的每一项里都放黑色主按钮
当前位置、已选中--accent-surface / --accent-text黑色背景
链接、可点的文字--text-link，悬停用 --accent-text只靠下划线或粗体
进度--progress-track / --progress-fill，同时配文字说明绿色进度条
成功、已完成--status-success / -bg / -text蓝色
提醒、限制--status-warning / -bg / -text黄色收藏色
失败、危险操作--status-danger / -bg / -text点赞红 --reaction-liked
内容分类--badge-{green|red|blue|amber|purple|yellow}-bg/-text用状态色表示分类
文字层级--text-heading → --text-primary → --text-secondary；禁用与占位用 --text-disabled用透明度调灰；用 #949494 写必读信息
键盘焦点--focus-ring 轮廓去掉 outline 却不提供替代反馈

表面与层级

层Token效果
画布--surface-canvas无边框、无阴影
主内容卡、工作空间--surface-default，--radius-card无阴影
次级区块（侧栏块、控件底色）--surface-secondary / --surface-hover无阴影
悬停相邻色阶 --article-surface-*-hover / --feed-surface-neutral-hover不加黑色遮罩
提示、轻提示--surface-default + --shadow-md—
菜单、弹层、导览面板--surface-default + --shadow-lg可以用 --glass-fill-strong + --glass-blur-strong，必须有实色回退
选中的分段、小控件浮起--shadow-sm—
浮动控件、滚动边缘--glass-fill + --glass-blur不覆盖整段正文
标签、话题等中性填充--fill-subtle → --fill-hover → --fill-selected，描边 --fill-border不用黑色透明度自行调配

停下来问人

遇到下面的情况不要自行决定，在 DISCUSSION.md 的“待确认”中写下需求、方案和理由。

  • 需要决策表以外的颜色、字号、圆角、间距或断点
  • 要改变现有组件的外观或行为
  • 新的交互方式：拖拽、手势、全屏弹窗、自动播放
  • 与决策记录中的任何一条冲突
